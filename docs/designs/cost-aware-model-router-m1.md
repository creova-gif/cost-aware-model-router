## Problem Statement

Developers running AI applications and autonomous agents face an inference economics trust gap. Open-source routing tools are split into two disconnected worlds: ML complexity routers (like RouteLLM) optimize routing on generic public leaderboards with no cost provenance, while gateway proxies (like LiteLLM) track raw token spend with no quality evaluator or replay proof. As a result, teams either overpay by sending every prompt to a frontier model or hesitate to enable automated routing because they cannot prove whether cost savings silently broke structured outputs or task accuracy on their own workload.

Milestone 1 solves the trust gap before introducing live proxy routing: given a representative workload (real or synthetic prompts), the system evaluates every request across three model tiers, measures or models cost, quality, and latency, and produces an interactive Pareto frontier alongside a tamper-evident, auditable savings receipt.

## What Makes This Cool

- **Live Pareto flight simulator:** Dragging a single cost-versus-quality slider in a zero-server interactive HTML report immediately updates the active routing policy, tier mix (Compact / Mid / Frontier), projected spend, quality pass rate, P95 latency, and per-request explanations directly from the embedded evaluation matrix.
- **Cost per successful outcome (goodput), not blind token cheapness:** Deployable policies (`static-tier`, `complexity-threshold`, `cascade-escalation`) are evaluated on cost per passing outcome under explicit quality floors, and benchmarked against a clearly labeled offline hindsight-oracle upper bound (`ear-oracle`, $\tau$-equivalence) so developers see both achievable savings and the theoretical ceiling.
- **Strict per-metric provenance discipline:** Every `ExecutionTrace` records provenance per metric (`tokens_provenance`, `latency_provenance`, `verdict_provenance`, `cost_provenance`), each tagged `measured`, `modeled`, or `unknown`. For live API calls, tokens, wall-clock latency, and evaluator verdicts are `measured`, while USD cost is `measured` only when the provider returns billed USD and `modeled` when computed from `PricingCatalog * measured_tokens`. Fixture replays tag all metrics `modeled`. Missing evaluators or unpriced models are tagged `unknown` and excluded from savings claims. No blended numbers, no marketing claims.

## Constraints

- **Engineering standards (`AGENTS.md`):** Python 3.12+, Pydantic v2 (`pydantic>=2.9`), `mypy --strict`, `ruff check`, deterministic `pytest` unit tests, zero bare `except Exception: pass`, ADRs in `docs/adr/`.
- **Security (`docs/THREAT_MODEL.md`):** Never commit `.env`, API keys, or PII/PHI fixtures; preserve `org_id` tenant scoping hooks; scan with `gitleaks` in CI; sanitize any live prompt/response logs.
- **Zero-API-key reproducibility:** Anyone cloning the repo must be able to run one CLI command (`cost-router demo`) with zero API keys, zero databases, and zero background servers to reproduce the full 3-tier Pareto frontier and savings receipt.
- **Hard Milestone 1 boundary:** Live OpenAI-compatible HTTP proxy, autonomous Agent Budget Thermostat, distributed state/Redis, and multi-tenant auth are explicitly deferred to Milestone 2+.

## Premises

1. **Zero-API-key reproducibility first, live adapters second:** Bundled deterministic replay fixtures power the default demo; an optional live `OpenAICompatibleAdapter` (supporting OpenAI and local Ollama via configurable `base_url`) runs the exact same pipeline when credentials/endpoints are configured. Native `AnthropicAdapter` is deferred to Milestone 2+.
2. **Strict per-metric provenance (`measured`, `modeled`, `unknown`):** Savings calculations include only evaluated, priced items, distinguish `measured` execution signals from `modeled` catalog-priced or fixture-replayed costs, and isolate `unknown` items outside savings totals.
3. **Deterministic, non-eval evaluators as the default quality floor:** JSON schema validity, regex/exact assertions, declarative JSON field predicates, and latency SLA checks guarantee 100% reproducible, zero-cost, arbitrary-code-free evaluation; an `LLMJudge` protocol hook remains optional.
4. **Distribution & UX = Python package + CLI + self-contained interactive HTML report:** Zero-ops single-file HTML report + JSON/Markdown receipts deliver the full interactive demo today while Pydantic v2 schemas power Milestone 2's FastAPI/OpenAI control plane.
5. **Control-plane-ready boundaries without dead code:** Schemas carry `org_id`, `agent_id`, `policy_id`, and OpenTelemetry span attribute hooks now, with zero unused proxy, Redis, or auth scaffolding in Milestone 1.

## Approaches Considered

- **Approach A (Minimal Replay CLI & Static HTML Report — rejected):** Fastest to ship (~2-3 days human), but hardcoded routing logic and missing declarative policy DSL would force a structural rewrite before Milestone 2.
- **Approach B (Control-Plane-Ready Core + Policy DSL + Self-Contained HTML Explorer — chosen):** Clean hexagonal Python 3.12 architecture with typed adapters, evaluator registry, declarative YAML/JSON routing policies, Equivalence-Aware Pareto optimizer, SHA-256 auditable savings receipt, and interactive single-file HTML explorer.
- **Approach C (Local FastAPI Shadow Proxy + Live SQLite Dashboard — rejected):** Pulls HTTP server, async workers, and SQLite state into Milestone 1, violating zero-ops single-command reproducibility and adding unnecessary setup friction before the optimization loop is proven.

### Core Data Flow

1. **Workload & Catalog Load:** Load a JSONL workload (bundled 60-prompt multi-category fixture covering JSON extraction, classification, summarization, SQL/code debugging, and multi-step reasoning) plus a versioned 3-tier model catalog (`compact`, `mid`, `frontier`) with `Decimal` per-1M input/output pricing and price-source metadata.
2. **3-Tier Execution / Replay & Per-Metric Provenance:** Run each workload item across all 3 tiers through `ProviderAdapter`. Fixture replays emit `ProvenanceTag.MODELED` for tokens, latency, verdict, and cost. Live `OpenAICompatibleAdapter` calls emit `ProvenanceTag.MEASURED` for tokens, wall-clock latency, and evaluator verdict; `cost_provenance` is `MEASURED` only if the provider response includes a billed USD field, and `MODELED` when derived from `PricingCatalog * measured_tokens`. Missing price entries or adapter errors emit `ProvenanceTag.UNKNOWN`.
3. **Deterministic Evaluation:** Run each `(request_id, tier)` output through its declared declarative `Evaluator` suite (`json_schema`, `regex_match`, `exact_match`, `json_field_predicate`, `latency_sla`) to produce typed `EvalVerdict` records (`passed`, `score` in `[0.0, 1.0]`, `latency_ms`, `failure_reason`). Items lacking an evaluator are tagged `UNKNOWN` and excluded from savings percentages.
4. **Policy Sweep, Escalation Accounting & Pareto Frontier:**
   - **Deployable pre-execution / runtime policies:** Evaluate baseline (`all-frontier`), `all-compact`, `all-mid`, `complexity-threshold` grids, and `cascade-escalation` (starts at `compact`, escalates to `mid` then `frontier` when a deterministic evaluator fails). For any escalated request, `total_cost_usd` and `total_latency_ms` **accumulate across every attempted tier** in the escalation chain.
   - **Offline hindsight-oracle upper bound (`ear-oracle`):** Clearly separated and labeled `ORACLE UPPER BOUND (non-deployable)` in optimizer output, receipts, and HTML charts. For each request $i$, let $s^*_i = \max_{t \in \{\text{compact}, \text{mid}, \text{frontier}\}} \text{score}_{i,t}$; `ear-oracle` selects the cheapest tier $t$ with $\text{passed}_{i,t} = \text{true}$ and $s^*_i - \text{score}_{i,t} \le \tau$ (breaking cost ties by lowest latency).
   - **Goodput & zero-pass edge case:** Compute `cost_per_successful_outcome_usd = total_cost_usd / passed_count` when `passed_count > 0`; when `passed_count == 0`, store `null` in JSON (render `∞` in UI) and treat the policy as strictly dominated by any policy with `passed_count > 0` (breaking zero-pass ties by lowest cost).
   - **1D slider to 3D Pareto mapping:** Compute the exact non-dominated Pareto frontier over deployable policies on `(total_cost_usd, pass_rate, p95_latency_ms)`. In `pareto-explorer.html`, the single cost-vs-quality slider sets a minimum `pass_rate` floor $q_{\min} \in [0.0, 1.0]$. The deterministic selection rule picks the deployable frontier policy with `pass_rate >= q_min` that minimizes `total_cost_usd`, breaking ties by lowest `p95_latency_ms`, then highest `pass_rate`, then lexicographical `policy_id`. If no policy satisfies $q_{\min}$, the UI displays an explicit infeasible-floor banner and highlights the highest-`pass_rate` policy.
5. **Auditable Receipt & Interactive HTML Report:** `savings-receipt.json` is self-contained: it embeds `workload_digest`, `catalog_snapshot`, the full redacted `evaluation_matrix`, `policy_results` (deployable vs oracle separated), and an `integrity` envelope (`algorithm: "sha256"`, `canonicalization: "sorted-keys-utf8-compact-json-decimal-strings"`, `digest`). `cost-router verify-receipt <path>` strips `integrity`, re-serializes the canonical payload with sorted keys, UTF-8, `separators=(",", ":")`, and fixed-precision string-encoded `Decimal` USD values, and verifies the SHA-256 digest to detect any semantic or payload tampering. The HTML report embeds the same redacted `evaluation_matrix` and `policy_results` in a single zero-CDN file.

### Security & Privacy Guardrails

- Live adapter credentials are read exclusively from environment variables (never serialized into receipts, HTML reports, or logs).
- **Zero raw prompt/response leakage by default:** Both `savings-receipt.json` and `pareto-explorer.html` serialize only `prompt_sha256`, `response_sha256`, task category, token counts, provenance tags, evaluator verdicts, and structured routing explanations. Raw prompt/response text is omitted by default and only included when explicitly enabled via `--include-redacted-text` passing through a redaction hook.
- **Zero `eval`/`exec` in evaluators:** Milestone 1 uses strictly declarative non-eval evaluators (`json_schema`, `regex_match`, `exact_match`, `json_field_predicate`, `latency_sla`). Arbitrary Python assertion execution is excluded from Milestone 1.
- `verify-receipt` validates Pydantic schema + canonical SHA-256 integrity without executing any untrusted code.

### Locked Engineering Decisions (D1–D3 + Review Hardenings)
- **D1 (Module Structure):** Flat 7-module package under `src/cost_aware_model_router/`: `schemas.py`, `adapters.py`, `evaluators.py`, `policies.py`, `receipt.py`, `report.py`, `cli.py`, plus `fixtures/`. Zero shallow pass-through `__init__.py` barrels.
- **D2 (`ear-oracle` All-Fail Fallback):** When all 3 tiers fail evaluation on a prompt, select the highest-scoring tier, breaking ties by lowest `total_cost_usd` -> lowest `latency_ms` -> tier order (`compact < mid < frontier`), and set `oracle_all_failed = true`.
- **D3 (2D Pareto Frontier + 1D Slider):** Compute the exact 2D Pareto frontier `(total_cost_usd, pass_rate)` over deployable policies so every frontier point is reachable by the 1D `pass_rate >= q_min` slider (tie-break: lowest `p95_latency_ms` -> highest `pass_rate` -> `policy_id`). Display `p95_latency_ms` and `cost_per_successful_outcome_usd` on every KPI card and receipt row.
- **Native Challenger Hardenings Adopted:**
  1. **Complete-case intersection for partial-tier `UNKNOWN`:** Exclude any request where *any* tier is `UNKNOWN` from cross-policy frontier/savings totals (reporting `excluded_count` explicitly); in `cascade-escalation`, an intermediate `UNKNOWN` marks the request `UNKNOWN` while tracking burned spend separately.
  2. **Cascade + `latency_sla` re-evaluation:** Re-evaluate `latency_sla` against cumulative cascade latency in `policies.py`, and short-circuit escalation if `compact` already violated `latency_sla`.
  3. **In-sample fit disclosure:** Tag grid-searched `complexity-threshold` policies `in_sample_fit: true` in receipts and HTML UI (optional `--holdout-fraction` supported).
  4. **Canonical integrity & honest framing:** Use `allow_nan=False`, fixed-precision string serialization for all floats (`score`, `pass_rate`, `latency_ms`, `p95_latency_ms`) and 8-place `Decimal` USD; `verify-receipt` hashes the parsed raw JSON dict (minus `integrity`). Frame unsigned SHA-256 honestly as integrity/drift detection, not cryptographic non-repudiation.
  5. **Security & live adapter guards:** Guard `regex_match` against ReDoS (length/complexity limit); embed HTML JSON via `<script type="application/json">` with `<` -> `\u003c` and build SVG exclusively via `document.createElementNS`/`setAttribute` (zero `innerHTML`); block `Authorization` headers over non-loopback `http://`, fail-fast on `401`/`403`/`404`, bound live concurrency (`Semaphore(8)`, `timeout=30s`, max 2 retries with `Retry-After` backoff), add `--max-cost-usd` spend guard; missing `usage` emits `tokens_provenance=UNKNOWN` + `cost_provenance=UNKNOWN`; defer `--include-redacted-text` to Milestone 1.5 (digest-only in M1).

### Failure Modes
| Path | Realistic Failure | Handling & Test | User Experience |
|---|---|---|---|
| `adapters.py` (live HTTP) | 429/500/timeout or missing `usage` | Bounded retry (2x) / fail-fast 401/403/404 -> `ProvenanceTag.UNKNOWN` | Explicit `UNKNOWN` count; excluded from savings |
